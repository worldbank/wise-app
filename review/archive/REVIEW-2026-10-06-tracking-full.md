### CR-SEC-09 step 2: report-only CSP, local test (2026-10-24)

**Inventory** (what the app loads): scripts and styles are all same-origin (Shiny, jQuery, bslib, htmlwidgets, echarts4r, reactable, vendored MapLibre GL and h3-js under `inst/app/vendor/`, katex); fonts are local (`inst/app/fonts/`, plus one `data:` font in an inline style); the only third-party host is `tiles.basemaps.cartocdn.com` (style JSON, sprite, glyphs and tiles, fetched by MapLibre in the page and in its blob workers); the Shiny websocket is same-origin; the CSV and PNG downloads are same-origin or `blob:`/`data:` links.

**Method.** `dev/ui_drive.R` cannot add a header, and Shiny has no hook for response headers (`shiny.http.response.filter` does not exist), so a scratch process attached to the same Chrome (port 9333) enabled the DevTools `Fetch` domain for Document responses, re-fulfilled the page with `Content-Security-Policy-Report-Only` added, and registered a `securitypolicyviolation` listener with `Page.addScriptToEvaluateOnNewDocument`; the ui_drive commands then drove the flow. The app ran on the generated fixture data (see CR-A11Y-09): Overview, Step 1 (survey stats with the hex map, outcome, weather, model), Step 2 run and diagnostics, Step 3 social protection run, decomposition, cost-effectiveness, the Export menu. Not covered: the actual downloads (CSV, PNG, export zip), hover tooltips, the real-data tile traffic, Databricks or cloud sources, anything behind a proxy.

**Strict probe** (`default-src 'self'`; `script-src 'self'`; `style-src 'self'`; `img-src 'self' data: blob:`; `connect-src 'self' wss: tiles.basemaps.cartocdn.com`; `worker-src 'self' blob:`): violations by directive over the flow, in distinct kinds: `style-src-attr` inline, 544 (the `style=` attributes of the app, bslib and Shiny); `script-src` eval, 221 (188 `echarts4r-binding`, 32 `htmlwidgets.js`, 1 `shiny.min.js`: `htmlwidgets::JS()` formatters); `script-src-elem` inline, 11 (bslib `Card.initializeAllCards()`, `Sidebar.initCollapsibleAll()`, and the page's `$(document).ready` Shiny bootstrap, none in the app's own code); `style-src-elem` inline, 3 (bslib spinner variable block, `html { height: 100% }`, the `.wx-tip` legend styles); `font-src` data, 1. No `connect-src`, `img-src`, `worker-src` or `frame-src` violation: the map drew (3 MapLibre canvases) with only `https://tiles.basemaps.cartocdn.com` allowed, and the websocket needs no `wss:` entry (`'self'` covers it in Chrome).

**Proposed policy** (adds `'unsafe-inline'` to `script-src` and `style-src`, `'unsafe-eval'` to `script-src`, `data:` to `font-src`): `default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self' https://tiles.basemaps.cartocdn.com; worker-src 'self' blob:; object-src 'none'; base-uri 'self'; form-action 'self'`. Result on the same flow: **no violations** (report-only; nothing was enforced). `frame-ancestors` is left out on purpose: report-only ignores it and Connect controls embedding.

**Where to set it.** Posit Connect: `CustomHeader` in the `[Server]` section of `/etc/rstudio-connect/rstudio-connect.gcfg` (HTTP headers page of the Connect admin guide). It applies to all content on the server, Connect's and the frameworks' own headers can overwrite it, and a server with several content types needs a policy that fits all. Because of that, an app-side header would be the alternative, but Shiny offers no supported hook for the main page (only `httpResponse` from a `ui` function, which bypasses Shiny's page rendering), so it is not recommended. Staging step (needs the user's go-ahead, not done): add the report-only header to a staging Connect instance, add a `report-uri` endpoint or read the browser console, collect real traffic for the data sources in use.

**Tool finding, fixed 2026-10-24.** `dev/ui_drive.R` registered its `window.__wiseErrors` hook only with `Page.addScriptToEvaluateOnNewDocument`, which ends with the CDP session (the process), so `errors` never reported uncaught JS errors. `connect()` now installs the hook in the current document on every call (guarded, once per document); errors thrown before the first call after a load are still missed. Checked: a thrown error is reported by the next `errors` call.
